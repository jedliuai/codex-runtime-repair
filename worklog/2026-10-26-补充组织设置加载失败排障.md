# 这次做了什么

把这次亲自验证有效的 Codex 桌面端修复方法整理进仓库：新增一份中英文排障指南，在 README 的两个语言区各加一个入口。指南包括完整路径检查、备份覆盖变量、清除用户级变量、重启验证和回退方法。

# 为什么要补这一份

这次桌面端提示“无法加载组织设置”，但同机 CLI 一直正常。排查发现 Process 和 User 的 CODEX_CLI_PATH 都指向 npm 安装的 CLI，Machine 为空。备份并清除覆盖变量、重启 Windows 后，桌面端恢复。需要把这个案例留下来，下次看到相同弹窗可以先检查具体条件。

# 值得记住的事

弹窗里提到网络不等于一定是公司网络或代理的问题。这个案例支持外部 CLI 覆盖变量会影响桌面端启动，但具体的协议不兼容细节没有独立确认，文档不能写成适用于所有人的万能修复。

原脚本处理的是 runtime 缓存半成品，和这次故障属于不同路径，所以只补文档，不改原 PowerShell 脚本、双击启动器或默认行为。命令必须先备份再清除，不改 Machine；重启 Windows 是为了让桌面进程读取更新后的环境变量。中英文共用一份修复代码，减少后续维护时命令不一致的机会。

提交前检查了三段 PowerShell 示例的语法和文档链接目标，没有实际执行会修改本机环境变量的示例。原修复脚本和启动器的 Git blob 哈希与修改前一致，变更范围只包含 README、独立排障指南和这份总结。

# 一句话亮点
